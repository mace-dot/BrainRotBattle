# Publish the standalone battle game

1. Build `build/BrainRotBattle.rbxlx` with Rojo, or download the place artifact from a successful GitHub Actions run.
2. Open it in Roblox Studio. Publish it as a **new experience** owned by your account/group. Keep it separate from the existing Rizzler-Roblox single-player place.
3. Set the place's **Max Players to 32** in Studio/Creator Dashboard so all eight four-player teams can fill. This setting is not configured by a GitHub push or Rojo script. Test with a local server and at least two clients. Check Studio Output for the `forest-team-battles-20261105b` build marker and startup errors.
4. Configure access/visibility in Creator Dashboard and verify the game with two real Roblox clients. Do not make it public until the multiplayer checklist passes.

The world and models are generated by `World.luau`; no purchased/imported models, private mesh IDs, or single-player Studio objects are required.

## Optional links to another game

The default experience is entirely battle-only. No destination is required to play.

If you want a **Single player** return portal:

1. Find the actual start PlaceId for the original single-player experience.
2. Set `SinglePlayerPlaceId` in `src/shared/Config.luau` to that numeric ID.
3. Rebuild/publish. A large orange **Single player** portal will appear in the battle holding room.
4. If cross-experience travel requires it, enable the relevant third-party teleport setting in the originating experience's Studio security settings.
5. Verify travel in the published Roblox client. Studio playtests do not verify actual teleports.

`BattlePlaceId` is an optional record of this game's published destination ID for external lobby integration. It is not needed for internal holding-room → arena movement, which remains on the same server.

To connect the original game's **Brain Rot battles** portal, update that original repository's portal callback to call `TeleportService:TeleportAsync` with this game's actual published PlaceId. Use a debounce and handle both synchronous errors and `TeleportInitFailed`. Show a visible retry message. That original repository is outside this change and has not been modified.

Never paste a GitHub repository ID or Roblox universe/experience ID in place of a PlaceId. Keep IDs at zero while unconfigured; the optional return portal remains hidden and the standalone battle game stays playable.
